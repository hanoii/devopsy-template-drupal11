History, not rules: AGENTS.md's Rules win where they differ.

- Compiled Twig once went to `public://php`.
- The `sites/` rule was a regex on the request path before: `evil.php/x`, `evil.php%2Fx` and `evil.PHP` ran, and a directory's `index.php` ran from `files/evil/`. Unanchored, the next match refused files like `my.pharmacy.jpg` and `report.php.pdf`, and their image style derivatives once written.
- Comparing `frankenphp adapt` by hand rather than in a build: the base floats, so a build failing on every FrankenPHP change would block releases.
- Only Drupal's entry scripts: php_server ran any PHP under the web root (checked: a module's `evil.php`, `vendor/autoload.php` and a directory's `index.php` ran, and core's fixtures answered 500), while Drupal's own Apache setup refuses it. `autoload_runtime.php` is a scaffold file newer than `.htaccess`'s rule. Checked against the built image run as compose runs it (10001, no capabilities, read-only, Drupal installed): the front page, `/index.php/...`, `/update.php` (logged in), `core/install.php`, `rebuild.php` and `authorize.php`, static files and image style derivatives reach what they did; everything else is a 403.
- No symlinks in public files: Caddy 2's file_server has no setting not to follow links, nor FrankenPHP (checked). Demonstrated: private files and the access log served through links the app could write (`public/p -> /app/storage/private`, `/app/logs`, `/proc/self/environ`), gone after a restart. Drupal never creates one there. `private -> public` would put private files where anyone fetches them, `public -> /app/logs` serve the log. Checked as 10001 on a Docker volume: links to a directory, to a sibling and dangling ones are replaced, and the start fails when the link cannot be removed (storage not the app's).
- MariaDB on `mariadb:11.8` rather than `mariadb:11`: downgrades are unsupported, and a plain release would carry the database across series.
- On 2026-11-03 the README's reference (How it works, Child environments, Rolling back, Changing configuration) moved into `docs/`, a doc per topic, since 367 lines had become what nobody read past the start, and the intro's line on what users read names `docs/` too.
- Static files' headers: under Apache, Drupal's `.htaccess` gives files a lifetime (mod_expires) and `nosniff` (mod_headers), and the Caddyfile gave neither, so browsers revalidated every CSS, JS, font and image on each page (ETag, 304). Older `.htaccess` versions said two weeks; the one Drupal 11 ships says a year, which the template follows. Aggregates are `immutable` since Drupal 10.1's names hash each file's contents (`AssetGroupSetHashTrait`). `public` was proposed and left out for basic auth's sake. The CSP was proposed for SVG only, and considered for every public file, which would also cover HTML and types Caddy sniffs, but reports of PDFs failing to render under a restrictive CSP (a Safari report, a Firefox bug fixed long ago), not checked here, kept it to SVG and HTML. Checked on a local stack with curl from inside the app: aggregates immutable, core's JS, PNG and `robots.txt` a year, an uploaded `T.SVG` in a subdirectory, an HTML file and core's logo SVG the CSP, a PDF none, `/`, `/sites/default/files/` and a missing aggregate or file Drupal's `must-revalidate, no-cache, private`, `/.htaccess` a bare 403, the headers kept on a zstd response and a 304, and the PHP checks unchanged.
- HSTS: a default middleware on Traefik's `websecure` entrypoint and an opt-in `hsts@file` from devopsy-template-traefik were both considered. Labels on the app's router won: Traefik's `headers` middleware needs no plugin, the policy stays the site's, and nothing ties a site's release to a Traefik release that defines the middleware. Only the app's router names it, since the middleware goes with the app's container while alwaysup answers. Checked on Traefik v3.7: the header on HTTPS, none on plain HTTP (as a tunnel's requests arrive).
